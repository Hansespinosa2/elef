# Build, Learn, Repeat

A retrospective for a team that shipped under pressure.

---

# What went well

- We made decisions in the open
- We shortened the feedback loop
- We protected the smallest usable release
- We asked for help before the deadline

---

# What felt hard

The work became noisy when every open question looked equally urgent.

We lost time switching between:

- customer feedback
- implementation details
- release coordination
- unresolved decisions

---

# The lesson

> Clarity is a delivery tool.

When the team names the decision, the owner, and the next checkpoint, momentum returns.

---

# One change for next cycle

Every project starts with a one-page decision log:

| Field | Example |
| --- | --- |
| Decision | Use the existing import pipeline |
| Owner | Priya |
| Checkpoint | After the first 20 files |
| Revisit when | Error rate exceeds 2% |

---

# A small commitment

Before the next kickoff, we will answer:

1. What are we trying to learn?
2. What is the smallest proof?
3. Who decides when the proof is enough?
