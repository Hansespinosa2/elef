# ADR-012: Retired container term replaced by Work and WorkFolder

- Status: Accepted
- Date: 2026-10-11
- Decider: Andres (owner)
- Confidence: settled — owner-frozen rename map; implemented across the tree in one campaign

## Context

The product called its unit of authored work by a slide-show term
(`deck`) in code, commands, IPC, storage prose, UI copy, tests, and
decision records. That term no longer matches the product: Elef authors
two kinds (presentations and documents) through one Work concept, and
the frozen map below had to hold everywhere, including inside the ADRs
themselves, which are normally stable records.

## Decision

The retired term is gone from the vocabulary. Identity is always
**Work**; containers, collections, and operations are **WorkFolder**;
user surfaces say Work (capitalized, mid-sentence too); slide-show
sense says presentation. One Work maps 1:1 to one WorkFolder, so
renamed identifiers carry equal values across the boundary
(`FileEvent.work_id` equals the WorkId 1:1; one Work per work folder).

Representative mapping (full map in the frozen campaign record):

- `DeckManifest` / `DeckSummary` / `OpenDeck` / `DeckPreview` /
  `DeckRecord` → `WorkFolder*`; `deck_*` functions and variables →
  `work_folder_*`; `decks.rs` → `work_folders.rs` (both crates).
- Tauri commands `list/create/open/read_preview/rename/delete_deck` →
  `*_work_folder(s)`; capabilities `allow-*` follow; generated
  permissions and schemas regenerated by the build, never hand-edited.
- `ImportResult.deck` → `work_folder`;
  `LibraryStatus.decks` → `work_folders`;
  `FileEvent.deck_id` → `work_id`;
  `x-elef-deck-id` → `x-elef-work-id`; menu id `open-deck` → `open-work`
  (the File/View double-use alias is preserved as-is).
- Transport wrappers keep the bridge/container sense (`listWorkFolders`,
  `readWorkFolder`, `mediaUrlsForWorkFolder`, `noteListedWorkFolders`);
  UI flows use the identity sense (`openWork`, `SaveWork`,
  `TitleSaveWork`, `prepareWorkOpen`, `onOpenWork`).
- DOM: `#deck-*` → `#work-*`, `.deck-action` / `.deck-warning` /
  `.presenting-deck` / `.printing-deck` → `.work-*`,
  `data-deck-id` → `data-work-id`,
  `dataset.loadedDeckId` → `loadedWorkId`.
- Link scheme `#deck/<id>` → `#work/<id>` (clean break, no compat).
- `spec/deck-manifest.schema.json` → `spec/work-manifest.schema.json`
  (`$id` URL and title follow; the `check_spec.py` enforcer pointer
  stays in the description).

Unchanged: the `.elef` extension, the `elef.json` name and its
`{ id, schema_version }` format, and the slide / slide-block
vocabulary. No database, migration, or route changes exist.

## Consequences

- Convention override (owner-approved, recorded here): ADRs
  001/003/005/006/008/010 and the ADR index were rewritten in place
  for this rename instead of staying frozen. The decisions, rationale,
  and acceptance evidence in those records are unchanged; only the
  retired term was replaced. Future ADRs use Work/WorkFolder.
- Clean breaks, no migration: the file-association identifier
  (`com.elef.deck` → `com.elef.work`), the archive MIME type
  (`application/vnd.elef.deck` → `application/vnd.elef.work`), the
  `#deck/` link scheme, Tauri command names, and IPC field names all
  change at once. Old OS registrations and old links do not resolve.
- This record and its index row intentionally name the retired term:
  a rename record cannot document its own mapping otherwise. They are
  the only sanctioned remainder of that term in the tree.
