# Elef Desktop — Test Strategy (testing seam)

Status: draft v3 (revised 2026-10-06). Implements the preference: one suite of user flows verified on web and desktop, tiered for speed, no divergent suites. Every quality scenario in [requirements.md](requirements.md) maps to a tier here.

## 1. Structure: shared scenarios, two runner dialects

- **Scenarios** are shared functions defined once against a small UI adapter. `edit-and-preview` opens a deck, edits source, waits for auto-save, exercises session undo/redo with each version persisted, uploads an image through the media controller, and verifies the rendered preview; `library-and-graph` checks card previews, case- and Unicode-normalized search, All/Presentations/Documents views, and opening a linked document from the graph; `library-create-delete` creates a presentation through each host's New action, verifies it appears in the library, and deletes it through the host confirmation; `appearance` changes theme and typography through the shared controller, saves their front matter, reopens, and verifies the rendered classes; `external-edit-conflict` changes the source outside the editor and verifies disk, local, and merged resolutions; `snippet-insert` selects a source snippet and checks the saved expansion; `math-input` selects a math shortcut, completes the display expression, saves it, and checks rendered math; `hostile-deck-neutralized` opens an adversarial deck and checks that executable markup, unsafe URLs, remote requests, and its attempted Tauri command have no effect. Desktop-only archive scenarios import a generated `.elef` through the running app's single-instance file-open path and export a deck through the desktop command, then compare per-file SHA-256 hashes. Each shared function must run through both adapters unless its browser-only or shell-only scope is documented.
- **Web adapter:** Playwright Test drives the Rails app in Chromium. **Desktop adapter:** WebdriverIO drives the real Tauri binary through its embedded WebDriver provider. Both adapters call the same scenario definitions; their page-object operations use their runner's normal APIs.
- The Tauri WebDriver bridge in CI does not reliably focus CodeMirror for keyboard input. Its page object updates the live editor through the existing input-proxy controller, which runs the same CodeMirror update, auto-save, preview, and conflict handlers. For authoring-palette selection it dispatches the option's existing `mousedown` event, whose handler performs the same insertion as a pointer selection. The web runner exercises keyboard and pointer input; desktop keyboard feel still needs the real-device acceptance check.
- The WebDriver-only desktop build may set `ELEF_E2E_EXPORT_PATH` to write an export into the isolated test directory instead of opening the native Save dialog. It invokes the same `export_elef` command and archive writer; production builds do not compile this path. A separate native smoke opens and cancels the Save dialog on both OSes; choosing a destination through the dialog remains a device smoke check.
- **Platform constraint:** [Tauri documents WebDriver for desktop automation](https://v2.tauri.app/develop/tests/webdriver/), while Playwright's CDP attachment is Chromium-specific. The desktop runner exercises the actual WKWebView/WebKitGTK and native command backend; the web runner exercises Rails in Chromium. This is the user's selected WebdriverIO trade-off for retaining Tauri.
- **Linux desktop session:** T2 runs under `dbus-run-session` because Tauri's single-instance plugin registers through the user D-Bus session. The `.elef` launch smoke verifies the expected D-Bus name before it starts the second process.
- **macOS offline confinement:** CI sets `ELEF_E2E_OFFLINE=1`. The WebDriver application launcher executes Tauri under `sandbox-exec`, including the second-instance archive smoke; the native Quit smoke is wrapped separately. The Seatbelt profile allows loopback and Unix sockets and denies external network access. Before the suite, a confined Node probe must connect to both IPv4 and IPv6 loopback listeners and receive a kernel permission error for external IPv4 and IPv6 connections. The WebDriver harness, Rails fixture setup, web scenarios, and Actions runner remain outside this restriction: the native smoke harness needs Apple-event permission to drive menus and cancel dialogs. The rules follow [Bazel's Darwin sandbox network policy](https://github.com/bazelbuild/bazel/blob/master/src/main/java/com/google/devtools/build/lib/sandbox/DarwinSandboxedSpawnRunner.java).
- **Isolation:** the app enables the WebdriverIO command plugin and embedded server only with the explicit `webdriver` Cargo feature, a separate E2E Tauri config, an E2E-only frontend directory, and a test-only capability. The production config, default Cargo features, and production frontend do not include those hooks.
- **Desktop-only boundary checks:** custom `.elef` snippet/math loading and refresh, snippet and math-shortcut settings CRUD with stale-write conflict detection and an in-flight tab-switch regression, unsupported/over-limit media rejection, and native menus/dialogs run only against the desktop binary because Rails has no local-library IPC or native shell. They complement shared behavior scenarios rather than creating another editor flow.
- **Native updater verification:** a separate loopback fixture process creates an ephemeral Ed25519 key entirely in memory and sends only its public key to the E2E binary. Six real-plugin checks cover no update, an older version, a valid signed download, corrupt bytes with a valid signature for different bytes, a truncated HTTP response, and a manifest version differing from the signed artifact version. Each asserts the installed binary and deck source hashes stay unchanged and the application still answers WebDriver. Resources are released after every check. `update_install` unit tests exercise file and directory activation with 50 process kills at each of four points per type (400 total): partial staging, before sync, immediately before exchange and immediately after exchange. Every launch path contains the complete old or new installation. Production key custody and Gatekeeper remain owner-device release gates.
- **Packaged update cycle:** `build-update-fixtures.mjs` builds isolated 0.1.0 and 0.2.0 packages with the E2E capability. The fixture server signs the actual N package in memory. The runner copies N-1 into a temporary installation directory and drives that installed application. The final desktop scenario cancels the native installation confirmation and checks unchanged bytes, then accepts it, installs N, checks the binary changed and deck bytes did not, and lets WebDriver close the old process. A second WebDriver session launches the original installation path and asserts the native version is 0.2.0 and the saved source is intact. The test uses ephemeral fixtures, not production signing keys, and does not publish a release.
- The Linux packaged runner uses the AppImage runtime's own extraction operation and starts the packaged executable with `APPIMAGE` set to the installed file. It repeats extraction after installation, matching the runtime's extraction fallback without requiring FUSE in CI. WebDriver owns the native process directly and checks the installed AppImage hash, rather than leaving a runtime child alive after cleanup. Temporary directories are canonicalized on macOS to avoid launching through `/var`'s symlink.
- **Current evidence:** the last complete PR run before the shared conflict-view change, [run 37375552222](https://github.com/Hansespinosa2/elef/actions/runs/37375552222), passed its Linux and macOS desktop jobs and the Rails test matrix. It covered the shared edit/save/undo/redo/media/preview, library, graph, disk/local conflict, snippet, math, and hostile-deck flows, plus native archive, dialog, updater, and performance checks. This change adds the merge resolution to the shared conflict component and scenario; the next PR run must verify that added path on web, Linux, and macOS. The Linux shared-scenario run blocks IPv4 and IPv6 egress while retaining loopback access. The hostile fixture attempts inline script, event handlers, a nested frame, remote fetch, parent messaging, unsafe links, and remote/data media; desktop also verifies the attempted `create_deck` IPC call created no deck. Desktop-only smoke opens a generated `.elef`, exports a deck, and compares every extracted file hash with its source folder. The T0 Rust suite kills a child at four save points, 50 runs per point; the current CI matrix includes this suite. Target-device performance, production signing/key custody, Gatekeeper, and the real-device use week remain release gates.
- **Divergence guard:** a scenario that exists in only one runner without a documented reason fails review.

## 2. Tiers

| Tier | What | When | Verifies |
|---|---|---|---|
| T0-fast | Frontend unit tests and Rust `elef-core` tests | Every configured CI event; `desktop-fast` job has a 5-minute timeout and asserts test-command runtime below 300 seconds | Core save, archive, path, renderer, transport, and UI unit coverage |
| T0 | Full unit and component suite: Rust core tests (safe write, path guard, archive, source-file rule, document graph, asset validation, four-point child-process save-kill matrix); Rails-owned JS behavior and UI tests from `test/javascript`; **renderer fixture suite** (Node, against the bundle); thin Ruby test that the MiniRacer wrapper returns the same HTML as the bundle; desktop transport contract tests | PRs | QS-2, QS-3 (Rust), QS-4, QS-5, QS-10, QS-11 |
| T1 | Playwright: shared scenarios vs **web** (Rails test server) | PRs | QS-1 (web leg) |
| T2 | WebdriverIO: the same scenario functions vs the **real Tauri binary**, through its test-only embedded WebDriver provider on Linux and macOS; native menu/dialog smoke and a CodeMirror keyboard-input smoke | PRs | QS-1 (shared edit/save/undo/redo/preview and library/graph flows), QS-4 hostile-deck probe |
| T3 | Native smoke: install, launch, user-initiated quit, menus, dialogs, updater dry-run, and hostile fixtures | PRs / release | QS-4, QS-5, QS-8 |
| CI fitness | Architecture rules as automated checks (§6) | Every change | QS-7, T5/T8 controls |

The `desktop-fast` job runs frontend and Rust-core unit tests for every configured CI event (pull-request updates and pushes to `dev` or `main`) and fails if the test commands exceed five minutes. T0's full suite and the T1/T2 shared scenario matrix gate PRs; T1/T2 run on both target OSes. The shared scenarios verify opening a deck, source/visual caret restoration, auto-save, document-link resolution after a saved-source rerender, session undo/redo, media upload and preview, library card previews and normalized search, All/Presentations/Documents filtering, graph navigation, all three external-edit conflict resolutions, snippet insertion, math input, and hostile-deck neutralization. The Linux T2 scenario matrix runs with outbound network blocked. Desktop smoke verifies `.elef` import and export round-trip hashes. Process-kill save fault injection runs in T0.

The desktop keyboard smoke sends text through WebDriver keyboard actions to CodeMirror, asserts a trusted `keydown`, and verifies the resulting source bytes on disk. Shared scenarios continue to cover the editing flow on both runners.

## 3. Renderer fixtures: one renderer, two phases

The JS Markdown block renderer and slide/document structure/editor-map/editable-projection functions are shared (ADR-007); source is owned by `app/javascript/lib/`, Rails calls it through MiniRacer, and desktop calls it from its worker. `test/javascript/fixtures/renderer-inputs.json` defines 14 representative cases: Markdown blocks, layouts/margins, highlighted code and Mermaid placeholders, all math delimiters and error/empty cases, editable blank/structured regions, positioned blocks, Unicode/CRLF/fenced separators, malformed directive warnings, hostile content, and both platforms' document routes and media URLs. Reviewed expectations in `renderer-outputs.json` include exact block HTML and the entire projection payload. Node tests execute the checked-in bundle; Rails tests call all three wrapper entry points and compare every HTML byte, map, warning, and style to the same expectations. Tests never regenerate expectations; `node script/update_renderer_fixtures.mjs` is an explicit maintenance command whose diff requires review. `npm run renderer:build` builds the Rails-owned artifact, which the desktop package copies byte-for-byte. This establishes cross-runtime parity for the corpus; comparison against the Ruby rollback and coverage of every read-only/export consumer remain cutover gates.

`SourceJavascriptRendererTest` additionally renders 80 inputs across four isolated thread contexts. Its fresh-process fork probe initializes the renderer as a preloaded master, disposes contexts through the Puma lifecycle hook, and renders in two workers with three threads each before the master resumes rendering. Contexts are reused per thread within their owning PID; an inherited cache fails explicitly. Every wrapper entry point bounds source bytes before evaluation. macOS CI runs this test file alongside renderer/model/PPTX tests.

- **Phase 1 — cutover gate.** Comparison is **normalized**: strip highlighter spans and classes and compare text plus document structure, or compare a canonical token stream. Allowed diffs are enumerated (highlighter markup only); anything else fails. 100% normalized pass is required before the Ruby renderer is deleted.
- **Phase 2 — after cutover.** Expected outputs are regenerated from the JS renderer and comparison becomes **exact**. The normalization machinery is retired, not maintained.
- Mermaid output is not a Node fixture concern (needs a DOM): fixtures assert the placeholder; diagrams render in T1/T2 scenarios.
- The thin Ruby wrapper test stays permanently: it guards the wiring, not the rendering.

## 4. Fixtures

- **Temp-dir libraries:** every E2E test builds a fresh library (decks, images, `elef.json` variants, and the nasty cases: missing manifest, multiple `.md`, case-only, canonical-normalization, and full-casefold collisions, duplicate UUIDs, `talk (conflicted copy).md`, read-only folder).
- **Scale:** generated library of 1,000 decks plus a 50 MB deck. Budgets are measured against these.
- **Hostile:** script-payload Markdown, `javascript:` links, traversal paths, zip-slip archives, symlink-entry archives, zip-bombs, pathological Markdown for render limits.
- **Transport contract tests:** same input → same output shape against the Rails endpoint and the desktop handler.
- **Determinism:** fixtures never depend on wall-clock, locale, or the developer's home directory.

## 5. Fault injection (QS-2, QS-3)

**Current implementation status:** T0 runs a child process paused at four save points (before writing the temp file, mid-write, after flush and before rename, and after rename), kills it, and verifies that the source is wholly old or wholly new and that the next open removes leftover save temps. Each point runs 50 times. The Rust workspace test passed locally; the same suite is part of Linux and macOS desktop CI. This simulates process termination, not physical power loss. A separate 50-save measurement asserts that the p95 interval from the final matching fingerprint check to rename is below 250 ms. Unit coverage and the shared real-binary external-edit scenario exercise conflict handling; this is not an exhaustive permutation proof for every possible external-writer ordering. The check/rename window remains a documented residual race and is disclosed in the editor.

## 6. Architecture fitness functions (CI)

Automated checks that keep the architecture from drifting:
- Ruby `Source::HtmlRenderer` is absent after cutover; Rails and desktop load a renderer bundle with the same hash (QS-7).
- Rails application/runtime source does not import desktop code; desktop packaging consumes the app-owned host markup, product styles, and shared modules. Architecture tests intentionally inspect selected desktop bootstrap/build files to enforce this direction. `desktop/` owns the `elef-core` filesystem crate, Tauri commands, and shell-specific bootstrap, transport, lifecycle, updater, and native window/menu integration.
- The shared conflict dialog and its styles live in `app/javascript/lib/editor_view.js` and `app/assets/stylesheets/application.css`; the desktop host page must not define a second conflict UI.
- The tracked `app/assets/builds/tailwind.css` matches a fresh Rails Tailwind build; desktop packages that checked-in output without booting Rails.
- Tauri capability file equals the command table in [transport-adapter.md](transport-adapter.md); no wildcard fs or shell permission.
- Shipped CSP equals the policy recorded in [security.md](security.md); `script-src` has no `unsafe-inline` / `unsafe-eval`.
- The test-only WebdriverIO plugins, global Tauri API, and frontend initializer do not enter the default production build or capability.
- CI compares the shared workflow imports and invocation counts in the web and desktop runners, and checks every desktop-shared npm package version against the Rails importmap pin. A changed shared flow or package pin must update both consumers together.
- `elef-core` has no dependency on Tauri crates.
- Live feature flags match the register in [delivery-plan.md](delivery-plan.md); each has a removal condition.
- `cargo audit` and `npm audit` pass or have a dated, recorded exception.

## 7. Performance measurement

The headless browser style comparison renders identical presentation/document fixtures with the Rails stylesheet and the desktop bundle plus native theme. It compares computed fonts, sizes, line heights, colors, layouts and widths, including an explicit two-column layout assertion. This is a DOM/style assertion in Chromium; it does not constitute inspected screenshots or full application-state reproduction. The real-binary shared flows additionally exercise the stylesheet in each system webview.

Protocol per [requirements.md](requirements.md) §8: release build, fresh process, p95 over ≥20 runs, scale fixtures. Linux perf truth is WebKitGTK, notably slower than Chromium for scrolling and large CodeMirror documents; T1's Chromium does not cover it, so the T2 desktop leg runs on real Linux hardware. Images go through the asset protocol and rendering runs in a worker — both are tested, not assumed.

`desktop/e2e/benchmark-native.mjs` runs the application protocol on both hosted CI OSes with a release-optimized binary and test-only embedded driver. It creates 1,000 deck folders and a 100-slide deck containing a 50 MiB unreferenced local asset, then launches 20 fresh processes. Startup is process launch to frontend/editor readiness after paint; open includes read, editor initialization, worker rendering, DOM insertion and the first paint; warm list includes scan, card construction and paint. The open timer stops after the shared two-frame paint helper. The harness drains later overview callbacks only to collect complete lifecycle diagnostics; that wait is outside the measured duration. It checks every byte from an input burst during actual saving and exercises the native close guard for each process. Nearest-rank p95 includes all samples. CI passes `--report-runner`: it performs all 20 runs, fails on functional or persistence errors, retains the measurements, and reports budget misses because hosted runners are not the MacBook Air or Omarchy target hardware. Running the harness without that option strictly enforces the unchanged §8 budgets and is the target-device M5 release gate. Sample JSON is retained even on failure. CI-host measurements do not establish target-device performance or physical keystroke fidelity; the dedicated native smoke covers the platform Quit shortcut.

## 8. Policies

- **Flakes:** quarantine on the second flake; fix or delete within the PR; no permanently quarantined tests.
- **Affected-first:** T0 selects by changed packages; shared T1/T2 scenarios and native T3 checks run on the PR gate.
- **Coverage is not a goal;** scenarios and quality-scenario measures are.

The pinned embedded driver implements element click as `el.click()`, including option elements. Native Appearance scenarios therefore set the validated select value and dispatch its ordinary input/change events, then verify the real controller, source save, reopen, and rendered classes. This proves the UI event contract; physical select/keyboard behavior remains a real-device check. macOS smoke targets direct native window/sheet buttons with AXPress; webview descendants cannot satisfy that action.

Native Quit smoke waits for the actual editor and loaded-deck readiness through the embedded WebDriver, then sends Cmd-Q or Ctrl-Q to the isolated CI process. Three fresh launches cover a clean deck, a paused unsaved draft, and a paused draft with an external file edit. Assertions independently inspect the process exit and source bytes. A conflict must keep the process alive, preserve both the external file and local buffer, and allow Quit only after the disk-version choice resolves it. The fixtures are task-owned sibling deck folders; the shared scenario deck is unchanged.
