# Elef Slide Position/Alignment Grammar — Specification v1.0

**Status:** decided by owner (Andres) through elicitation on 2026-10-09.
**Visual references:** `elef-align-grammar-20.html`, `elef-align-grammar-stress.html`,
`elef-align-grammar-round2.html`, `elef-align-grammar-round3.html` — every preview in
those files is generated by an embedded JS implementation of these rules plus the
app's real slide CSS. When this spec and a mockup disagree, the mockup wins and this
spec must be corrected.

**Scope:** the vertical/horizontal placement of blocks on slides via `:::` directives.
Covers the JS renderer, the Ruby server renderer (present/print), CSS, and PPTX export.
Does NOT cover: the `center center` → `middle center` vocabulary migration (separate
work), the Tailwind-preflight-missing-in-presentation-layout discrepancy (separate
issue — do not fix here), or the `:::` container-removal work (separate work that this
depends on: directives already bind single blocks).

**How to read the labels:**
- **[DECIDED]** — elicited and locked. Implement exactly.
- **[OPEN]** — deliberately unresolved. Do not invent behavior; either ask or pick
the smallest consistent option and flag it in the PR.

## 1. Directive syntax [DECIDED] (existing behavior, restated)

- A directive line matches `^\s*:::(align|position)[ \t]*\{([^}]*)\}\s*$`.
  `align` and `position` are aliases.
- Values are whitespace-separated, case-insensitive.
  Horizontal ∈ {`left`, `center`, `right`}; vertical ∈ {`top`, `middle`, `bottom`}.
  `center` is **horizontal-only**; there is no vertical `center`.
- **Single-block binding:** a directive applies to exactly the Markdown block
  immediately below it. A block is any run of lines uninterrupted by a blank line.
  There is no container/group syntax; a bare `:::` line is meaningless and dropped.
- A directive with no block below it ("dangling") is dropped **+ warning**.
- Unknown directive names are dropped (existing orphan-warning plumbing).

## 2. Defaults [DECIDED]

- A block with no directive, or no position, is `left top` with a content-sized box.
- This is rendered **explicitly** as `position-left position-top` classes — never via
  inheritance. (Intended visible change: blocks with no directive no longer inherit
  statement-slide centering.)
- `position-top` has no CSS rule (top is the default); the class is inert but explicit.

## 3. Vertical grammar [DECIDED]

### 3.1 Middle stacks — the symmetric hug

A block with vertical `middle` anchors a **stack**:

```
        ┌─────────────────────────────────┐
        │  preceding top blocks: stay put  │  (Q1a — e.g. kicker pinned top)
        ├─────────────────────────────────┤
        │  ┌───────────────────────────┐  │
        │  │ preceding bottom blocks   │  │  ◄── hug from ABOVE
        │  │ middle block(s)           │  │  ◄── anchor (consecutive merge)
        │  │ following top/middle      │  │  ◄── hug from BELOW
        │  └───────────────────────────┘  │
        │        stack: margin-top:auto     │
        │               margin-bottom:auto  │  ◄── centered as one unit
        ├─────────────────────────────────┤
        │  bottom lane (trailing bottoms)  │  ◄── pinned to bottom
        └─────────────────────────────────┘
```

- The stack absorbs **following** blocks while their vertical ∈ {`top`, `middle`}
  (top hugs from below). Consecutive `middle` blocks merge into one stack.
  An explicit `top` joins. Each block keeps its own horizontal alignment and a
  content-sized box; inner blocks get no vertical auto-margins of their own.
- The stack absorbs **preceding** blocks while their vertical ∈ {`bottom`}
  (bottom hugs from above — symmetric with top). (Defensively also `middle`.)
- Blocks beyond the hug stay put: a `top` block before the opener stays in normal
  top flow; it is never pulled in.
- Headings participate uniformly: a `##` heading with `middle` opens a stack for
  its column like any other block (11a).
- The stack is centered as a unit in the remaining space via
  `margin-top:auto; margin-bottom:auto` on the stack wrapper.
- A lone `middle` block is a stack of one — identical to today's behavior.

### 3.2 Bottom lane

- `bottom` pins **only in the trailing run** of a flex context (slide body, or one
  column). A bottom block absorbed into a stack from above (§3.1) is exempt.
- Trailing bottom blocks render in a **bottom lane**: one lane per context, carrying
  the single `margin-top:auto`, pinned to the bottom. Blocks stack vertically and
  snugly inside it — bottom is the exact opposite of top.
- **Two blocks never implicitly share a row.** Side-by-side layout requires `##`
  columns. (Explicit rejection of implicit row-sharing.)
- A `bottom` block that is neither absorbed nor trailing is treated as `top`
  **+ warning** (actionable: "only trailing bottom blocks pin"). Source order is
  never reordered.

### 3.3 Docking

- A stack immediately before bottom content (lane) keeps only its top auto-margin
  (`flush-bottom`), so the lane pins exactly to the bottom edge.

### 3.4 Column titles

- In two/three-column layouts, the extracted H1 title's vertical is forced to `top`
  (horizontal alignment kept). Rationale: the title is layout chrome; a self-centering
  title breaks the columns. (13b)

### 3.5 Columns

- Each column is an independent flex context: stacks and lanes are computed per
  column. The extracted title is outside the columns.

## 4. Layouts (existing — unchanged by this spec)

Body / statement / two-column / three-column inference, region grouping, and title
extraction keep their existing rules. This spec only changes how `top`/`middle`/
`bottom` blocks are placed within those layouts.

## 5. What this fixes (reproduce first)

Render `Presentation::DEFAULT_SOURCE`:

```markdown
:::align{center center}
# Elef

:::align{center}
Your second brain for ...
```

**Today:** the title's own top/bottom auto-margins center it alone; the subtitle starts
after the large bottom auto-margin — a big gap between title and subtitle.
**After:** title vertically centered, subtitle snug directly beneath it (one stack).

(Note: the template still says `center center` until the vocabulary migration lands;
`center` in vertical position parses as `middle` under current code. Fixtures below
use the canonical `middle center` form.)

## 7. Implementation map

| Area | File(s) | Change |
|---|---|---|
| JS renderer | `app/javascript/lib/renderer.js` | Compute stacks (forward+backward per §3.1) and lanes (§3.2) per slide/region; emit `.slide-middle-group` / `.slide-bottom-lane` wrappers; neutralize inner vertical auto-margins; map null position → `position-left position-top`; force column-title vertical to top |
| CSS | `app/assets/stylesheets/application.css` | `.slide-middle-group` (auto/auto, flex column), `.flush-bottom`, `.slide-bottom-lane` (flex column, `margin-top:auto`), neutralize `.slide-bottom-lane .slide-block.position-bottom` margins |
| Ruby renderer | `app/lib/source/block_renderer.rb`, `app/views/presentations/_slide.html.erb` | Same grouping for server-rendered present/print, including column-title vertical forcing |
| PPTX export | `app/javascript/controllers/pptx_export_controller.js` | Mirror the grouping where blocks are re-rendered for measurement |
| Editor | `app/javascript/lib/renderer.js` (controls) | Keep per-block controls (`data-block-index`, Align select) correctly associated across wrappers |
| Warnings | existing plumbing | Reuse the orphan-directive warning surface; no new UX |

**Parity requirement:** JS renderer, Ruby renderer, and PPTX measurement must agree on
grouping for every fixture. Print output must be verified visually once.

## 8. [OPEN] items — do not invent; flag in the PR if forced to choose

1. **Warning surface:** reuse existing orphan-directive warnings. If no suitable
   surface exists for the "non-trailing bottom" warning, implement the smallest
   consistent one and flag it.
2. **PPTX lane mapping:** mirror the DOM grouping for measurement. If PPTX shapes
   cannot represent the lane faithfully, approximate (bottom-pinned text boxes) and
   flag the approximation.
3. **Overflow:** a stack taller than the slide/column clips top+bottom equally
   (flexbox-natural, same as today's lone-middle overflow). Conscious non-decision;
   do not "fix".
