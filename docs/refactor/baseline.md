## Existing architecture and ownership checks

Three existing checks enforce useful but incomplete pre-migration boundaries:

|---|---|
| `script/check_frontend_ownership.py` | Keeps the current Rails-owned shared source one-way: Rails source cannot import desktop files or Tauri APIs; desktop cannot author its own HTML/CSS UI; shared modules must resolve through Rails importmap pins; shared dependency versions must agree; renderer and shared workflow consumers stay aligned. This is a transitional Rails-to-desktop ownership rule, not the target package boundary. |
| `desktop/scripts/check_architecture.py` | Compares the Tauri command build allowlist, runtime registration and capability permissions; enforces CSP and test-only WebDriver permissions; checks signed HTTPS updater configuration, deferred feature flags, shared asset/style ownership, required shared workflow exports and renderer bundle hash identity. |

There was no repository-level `bin/check` command before this phase. Current product code remains outside the v9 target layout: Rails is rooted in `app/`, Tauri in `desktop/`, the local persistence core in `desktop/crates/elef-core`, and shared browser source in `app/javascript/`. Top-level `apps/`, `packages/`, `crates/`, `spec/`, `tests/`, `tooling/` and `ops/` are absent. This is staged migration work, not a Phase 00 reason to move code: Phase 01 establishes contracts, workspaces, `local-store` and tier tooling; Phase 03 gives Work semantics and rendering their owners; Phase 04 starts the client; Phases 05–09 migrate feature slices and remove product Stimulus ownership; Phase 10 completes cross-host parity; Phase 11 rehomes the hosts and operations. The detailed violation/owner/removal-phase register is in `baseline.json`.

## Persistence, identity and product behavior

While a desktop deck is open, `app/javascript/lib/file_library_application.js` polls its source snapshot every 2,000 ms. `desktop/crates/elef-core/src/lib.rs` fingerprints selected source files, rejects stale saves, writes through atomic replacement and retains external bytes in conflicts. `app/javascript/lib/save_flow.js` offers reload, keep-local and merge paths, and `test/e2e/scenarios/external-edit-conflict.js` exercises the shared conflict flow. Rust core tests cover external snapshots, save conflicts, interrupted writes and atomicity. ADR-008 documents a remaining external-writer race between the final fingerprint check and rename; a CI test keeps that synchronous window below a 250 ms p95 ceiling. The race is documented as residual risk, not claimed eliminated.

`app/lib/document_links/graph.rb` sends database IDs, title, URL, portable document key, aliases and source into shared renderer code. `app/javascript/lib/document_links.js` resolves explicit `document:` keys, IDs, aliases and titles and leaves ambiguous keys unresolved. ADR-010 stores `elef_document_key` and `elef_aliases` in Markdown front matter; desktop deck UUIDs are in `elef.json`.

`docs/desktop/adr/README.md` lists ten ADRs: 001, 005, 006, 008 and 010 are accepted; 002, 003, 004, 007 and 009 remain proposed. ADR-001's old last-write-wins rule is superseded by ADR-008. Open issue [#126](https://github.com/Hansespinosa2/elef/issues/126) records Preview differences (web saved read-only view versus desktop editable visual editor), Present differences (web publishes a release versus desktop presents the local draft), missing desktop fork actions, deferred lineage, renderer parity and rollback evidence. Issue [#128](https://github.com/Hansespinosa2/elef/issues/128) tracks target-device install/performance, update failure recovery, residual race acceptance and a real-use soak; [#129](https://github.com/Hansespinosa2/elef/issues/129) tracks updater signing-key custody and backups.

## Hosts, routes, deployment and URLs

`config/routes.rb` assigns Rails the root library and web routes for settings, search, snippets, math shortcuts, documents, presentations, media, history, export, publishing and fork actions. `app/views/layouts/application.html.erb` is the Rails layout with Rails CSRF/CSP metadata, importmap tags and Rails-built navigation. `app/views/desktop_host.html` is the static Tauri shell; `desktop/frontend/build.mjs` inserts a shared static authoring-settings partial and packages Rails-owned styles/modules for offline use.

`desktop/src-tauri/tauri.conf.json` registers `.elef` file associations and an HTTPS updater endpoint. Tauri also registers the `elefasset` URI scheme for scoped local media assets in `desktop/src-tauri/src/lib.rs`; this is an asset transport, not an application deep-link handler. No custom product deep-link URL scheme is registered. Web-only server operations such as publishing, history, fork and database-backed library/settings routes have no corresponding desktop HTTP pages. Desktop uses local filesystem/library commands and remains usable offline.

`Dockerfile` builds Rails assets in the Ruby 3.4 Trixie image and retains Node.js in that single-stage image. `docs/mac-mini-deployment.md` describes separate `dev/`, `prod/` and machine-local `ops/` trees, private Compose volumes, the deployment-ref watcher, loopback ports 3000/3001 and health checks. The watcher install and machine operations are not present in this checkout; this work did not invoke those commands or change deployment configuration. CI publishes a deployment ref only after exact tested-tree authorization through `scripts/verify-deployment-authorization` and `scripts/publish-deployment-ref`.
