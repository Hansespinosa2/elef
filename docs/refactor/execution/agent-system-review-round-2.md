## Findings

**P1 — Phase 00’s P00-01 proof is out of step with the gate sequence.** P00-01 requires `bin/check phase 0` to verify that status names the actual base and head ([Phase 00 contract](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/docs/refactor/phases/00-baseline.md:34), [automatic checks](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/docs/refactor/phases/00-baseline.md:41)). The campaign flow runs that check while the candidate is in DO, then sets `head_sha` to the candidate afterward ([campaign skill](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/SKILL.md:23)); the state protocol defines `head_sha` as the candidate ([state protocol](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/references/state-protocol.md:22)). The checked-out candidate therefore contains the pre-check status snapshot. The helper accepts an ancestor SHA rather than requiring an exact head match, so `validate` can pass without resolving this criterion ([campaign_state.py](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/scripts/campaign_state.py:522)). A fresh startup report also records this mismatch in its isolated checkout ([go acceptance](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/docs/refactor/execution/go-acceptance.md:10)).

Resolve what “actual head” means and make the proof occur when that value is available. For example, make P00-01 an explicitly checked postcondition after the CHECK status commit, or change the gate flow to validate a candidate status snapshot without changing candidate identity. Until then, Phase 00 cannot truthfully claim its promised automatic proof.

**P2 — BLOCKED can validate with inconsistent phase counters, then fail on recovery.** Validation exempts every BLOCKED state from the `current_phase`/`last_completed_phase` consistency check ([campaign_state.py](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/scripts/campaign_state.py:619)). A stale `last_completed_phase` can therefore leave BLOCKED valid even though restoring its `resume_state` makes validation fail. Require blocked states to preserve the same phase-position invariant, or define and test any supported exceptions.

**P2 — Cleanup and retries do not check whether an asynchronous process is still active.** Gate preparation can create another attempt without checking for a prior running one; `run_gate` records the helper PID, then starts the checker as a subprocess ([campaign_state.py](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/scripts/campaign_state.py:766)). Gate cleanup checks only worktree identity and Git cleanliness ([campaign_state.py](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/elef-campaign/scripts/campaign_state.py:740)). Reviewer cleanup has the same limitation: a clean worktree can be removed without checking for a live reviewer or collected report ([review_bundle.py](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/.agents/skills/independent-phase-review/scripts/review_bundle.py:43)). After an interrupted session, this can overlap heavyweight checks or remove a worktree still in use. Persist a child/session identity and terminal state; refuse retries or cleanup until the prior process is confirmed complete or stopped.

**P3 — The development guide leaves the protected server rule ambiguous.** Root instructions prohibit testing against the owner’s server ([AGENTS.md](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/AGENTS.md:46)), while the development guide says to “use” that endpoint ([docs/development.md](/home/andres/GitHub/elef-worktrees/feat-refactor-desktop-and-web/docs/development.md:9)). The verification skill clarifies that automated checks must not target it. Label the endpoint as interactive preview use and direct automated checks to isolated test environments.
