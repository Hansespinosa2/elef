## Intent

**Problem:** Elef currently renders and edits slides but offers no direct way to add or delete one. Keyboard movement also stops at slide boundaries, making a presentation feel like separate trapped editors instead of one continuous Markdown document.

**Approach:** Add contextual slide controls to the existing stacked preview, preserve `---` as the canonical visible Markdown separator, and make caret movement cross slide boundaries at the top and bottom of adjacent slides.

## Boundaries & Constraints

**Always:** Keep Markdown source canonical and portable. Add inserts one blank slide immediately after the current slide and focuses it. Delete acts immediately on the active slide, focuses the slide that takes its place, and exposes Undo. Deleting the only slide clears it without leaving zero slides. Up at the first line crosses to the previous slide's end; Down at the last line crosses to the next slide's start. Preserve existing inline editing, autosave, browser/Tauri behavior, math serialization, fenced-code parsing, and accessibility focus styles.

**Ask First:** None; the UX decisions are captured in the approved UX handoff.

**Never:** Do not hide or replace `---` with proprietary state. Do not require confirmation for routine deletion. Do not make controls hover-only or remove the final blank slide. Do not alter Markdown parsing semantics inside fenced code blocks or front matter.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| ADD_SLIDE | Active slide in a multi-slide presentation | Insert a blank slide after it, update source with a separator, focus the new slide | Keep source unchanged if the operation cannot be applied |
| DELETE_MIDDLE | Active slide 2 of 3 | Remove slide 2, former slide 3 takes its place and receives focus, show Undo | Retain deleted source until Undo expires |
| DELETE_ONLY | One-slide presentation | Clear content and retain one blank slide | Never produce zero slides |
| UNDO_DELETE | Delete followed by Undo | Restore exact source, ordering, focus, and scroll position | Keep current source if restoration is no longer valid |
| BOUNDARY_KEYS | Caret at first/last line of a slide | Up/Down crosses to adjacent slide; ordinary arrow behavior remains unchanged elsewhere | No-op at document outer boundary |
| SEPARATOR_INPUT | User types standalone `---` | Parser recognizes a new slide while source keeps the separator | Ignore separators inside fenced code and front matter |

**Acceptance Criteria:**
- Given an active slide, when Add slide is activated, then a blank slide appears immediately after it and receives focus.
- Given slide 2 of 3 is active, when Delete slide is activated, then slide 2 is removed, former slide 3 becomes active, and Undo is available.
- Given one remaining slide, when Delete slide is activated, then its content is cleared and one blank slide remains.
- Given a deletion with Undo still available, when Undo is activated, then the exact previous Markdown and slide order are restored.
- Given the caret at the first line of a non-first slide, when Up is pressed, then the caret moves to the end of the previous slide.
- Given the caret at the last line of a non-last slide, when Down is pressed, then the caret moves to the start of the next slide.
- Given a standalone `---` is typed, when the source is parsed, then it creates a slide boundary and remains in the Markdown source.
- Given a separator-like line appears in front matter or a fenced code block, when the source is parsed, then it does not create an unintended slide.
- Given either browser or Tauri mode, when slide editing changes source, then the existing persistence and preview flows continue to work.
