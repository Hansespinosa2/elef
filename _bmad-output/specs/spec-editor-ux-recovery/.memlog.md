topic: Recover slide editor UX with CodeMirror-backed TDD
updated: 2026-08-18T19:48
---

- (direction) Keep CodeMirror as the canonical document, selection, history, undo/redo, keybinding, TeX, autosave, and recovery authority while restoring the polished pre-CodeMirror slide editing experience.
- (constraint) Do not use whole-slide contentEditable or allow React-rendered DOM and browser editing to compete for ownership.
- (constraint) Edit mode must visibly remain a coherent stack of slides; Present mode owns full-screen fixed 16:9 playback.
- (event) Baseline audit found the fast suite passes 60 current unit/integration tests, while the pre-migration presentation integration file had 21 scenarios and the immediate migration reduced it to 5 before later additions; Tauri E2E is separate and not part of npm test.
- (event) Initial recovery contract and behavior matrix drafted for human review before TDD implementation.
- (decision) Rendered widgets are read-only projections; widget interactions dispatch explicit CodeMirror source transactions, matching Obsidian's source-authoritative model.
- (decision) Use Obsidian-style reveal units: simple Markdown reveals locally; fenced code, display math, tables, and inherently multi-line structures reveal as bounded units.
- (decision) Overflow remains inline with a temporary scrollbar and small non-blocking warning; users continue editing and split explicitly later.
- (decision) ArrowUp/Down uses native movement within slides and hands off only at the true first or last visual line to the adjacent slide.
- (decision) Standalone --- is always Elef's structural slide delimiter; alternate horizontal-rule syntax remains available.
- (decision) Rendered clicks use best-effort character mapping with deterministic line or structured-unit fallback when exact mapping is unavailable.
- (decision) Newest in-memory source remains authoritative during persistence; sequenced debounced saves and retries never overwrite newer edits, and close or presentation switch flushes or safely queues the latest source.
- (decision) Rendering failures preserve raw source and show a non-blocking fallback state; they never throw or replace source.
- (decision) Task checkbox clicks follow Obsidian's direct interaction pattern: toggle only the Markdown marker through a source transaction without revealing surrounding source.
- (decision) Edit mode uses minimal contextual controls: boundary add/delete on hover or focus, overflow split controls only when needed, and global actions in a small toolbar.
- (event) Stress-test coherence pass: resolved source authority, reveal units, overflow, arrows, delimiters, persistence ordering, rendering fallback, task interaction, and control placement; one mapping heuristic question remains.
- (event) Stress-test preservation pass: accepted decisions are represented in SPEC.md constraints and behavior-matrix red tests; no load-bearing decision was intentionally dropped.
- (decision) Write the complete behavior-matrix test set before production changes, map each category to model, integration, persistence, or browser tests, then implement slices sequentially behind red tests.
